About

The Vortex Workshop brings together Vortex developers, contributors, and users from academia and industry to discuss Vortex-related research. The Vortex Tutorial is held in conjunction with the workshop, providing an introduction to Vortex and its use in research and teaching.

The workshop offers an opportunity to share ongoing efforts in Vortex development or research using Vortex, thereby fostering the Vortex and broader open-source GPGPU community. Recent editions have featured work from Georgia Tech, UCLA, UC Berkeley, imec/KU Leuven, EPFL, NTUA, TU Munich, Université Grenoble Alpes, Columbia, and the University of Wisconsin–Madison.

Workshop Session

Talks are presented 10:40–11:40 in Part 2.

  • Transformer inference is typically evaluated on specialized accelerators or proprietary GPU platforms, leaving fewer opportunities to study the workload on an open-source GPU stack. In this paper, we present TinyGPT on Vortex, an OpenCL implementation of decoder-only transformer inference for the Vortex open-source RISC-V GPGPU. Starting from the sequential code of llama2.c, we map the main inference operations to programmable GPU kernels and validate the resulting implementations against the original CPU computation before deployment on an AMD Alveo U250 FPGA. We use a TinyStories-15M checkpoint to evaluate several Vortex hardware configurations with repeated autoregressive generation runs and choose the best-performing configuration to study a targeted attention optimization. Among the baseline configurations tested, 2c8w8t achieves the highest throughput. Fusing the three attention stages into a single kernel on the same hardware improves aggregate generation throughput by 1.74% while reducing mean dynamic instruction count by 35.08%. The resulting framework provides a working platform for studying the interaction between transformer software organization and Vortex GPU configuration.

  • GPUs are increasingly considered for use in safety critical systems in order to satisfy the computational demands of high automation. However, safety critical systems have particular requirements that differ from general purpose GPUs. In this abstract, we provide a summary of research works performed around Vortex, in order to meet these requirements.

  • Processing-near-memory (PNM) places compute where memory is manufactured, and because proximity is assumed to have already hidden the latency that a cache exists to hide, the cache then looks to be a good candidate to remove when a core must shrink to fit. We test this assumption through a design-space exploration with Vortex, the open-source RISC-V GPGPU, in which we sweep the data cache in capacity, associativity and presence across seven memory-proximity settings and 24 OpenCL benchmarks, with every configuration placed and routed on ASAP7. Proximity does not make the cache redundant: at the closest placement we model, a cacheless core reaches only 0.966× the performance of a cached core left at conventional distance, and parity would require memory roughly 14× closer than conventional, because a shorter access period makes each memory transaction cheaper while the cache decides how many transactions a warp’s accesses become. The cache should therefore be shrunk rather than removed, and its axes are not interchangeable: reducing capacity from 16 to 4 KB returns 12% of core area for 1.4% of performance, reducing associativity from four-way to direct-mapped returns 41% of core power for 2.2%, whereas removing the data cache costs 5.2% with the instruction cache kept and 18% without it, and compared with a direct-mapped cache it saves no power at all.

Poster Session

Posters are presented during the 10:10–10:40 break.

  • The rapid growth of Deep Neural Networks (DNNs) and Large Language Models (LLMs) has intensified the demand for efficient matrix multiplication, while the increasing sparsity of weights and activations creates additional opportunities for acceleration. Modern GPUs employ specialized units such as Tensor Cores to accelerate General Matrix Multiplication (GEMM). However, their performance is increasingly constrained by operand delivery staging and limited support for sparsity, particularly when both operands exhibit unstructured sparsity. In this work, we present a dual-operand unstructured sparse Tensor Core unit (TCU) that directly accesses operands from shared memory, reducing Register File traffic and improving operand delivery to the compute units. The proposed architecture adopts an outer-product execution model with bitmap-based sparse encoding, eliminating costly nonzero-index intersection and enabling unstructured sparsity to be exploited in both input operands. We further introduce the required ISA extensions and optimized GPU kernels, together with microarchitectural optimizations that improve utilization of the sparse compute datapath. Experimental evaluation demonstrates a mean speedup of 5.6×, a peak speedup of 26×, and up to 1.89× FlashAttention speedup, with 3.5% area and 2.2% power overhead over the dense-TCU baseline.

  • Vortex integrates a tensor compute unit (TCU) within each SIMT core, routing matrix operands and accumulators through the register file and coupling matrix operations to the SIMT datapath. We present DTCU, a cluster-level disaggregated tensor unit for the Vortex RISC-V GPGPU, modeled in SimX. A 64-byte descriptor launches a tiled GEMM, while a tensor memory access (TMA) engine overlaps data movement with computation through double-buffered SRAMs. An XOR swizzle eliminates bank conflicts for column-wise operand reads. On π0 and ACT GEMMs, DTCU shows 3.3–3.4× speedups with 0.12–0.14× the memory traffic of the in-core TCU at the same MAC array width. Fused kernels range from 2.4× speedup for ReLU to no gain for softmax, limited respectively by the global-memory hand-off and an epilogue-dominated characteristic.

Call for Papers

We invite submissions describing new microarchitecture, compiler, runtime, tooling, or application work built on or evaluated with Vortex, as well as experience reports on using Vortex in research and in the classroom.

Topics of interest

Topics of interest for the Vortex Workshop include, but are not limited to:

  • Design and implementation of Vortex GPGPU
  • OpenCL/CUDA running on Vortex
  • Compiler optimizations for Vortex
  • Memory hierarchy and management in Vortex GPGPU
  • Tensor cores, sparse units, and other domain-specialized units
  • Machine learning, graphics, and neural rendering on Vortex
  • Benchmarking and performance evaluation
  • Applications and case studies using Vortex
  • Security, reliability, and fault tolerance in GPGPU architecture
  • Comparison of Vortex with other GPGPU architectures
  • FPGA/ASIC implementation of Vortex

Submission guidelines

Authors are invited to submit 2-page papers, which must be formatted in accordance with the ACM two-column style. ACM Word or LaTeX style templates are available here. References do not count toward the page limit.

Note: Workshop publications do not preclude publishing at future conference venues.
